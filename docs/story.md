# The story behind my Niri setup

Most of my computer time these days falls into two halves: being on the internet
in Chrome, and tinkering or building something in a terminal, often with coding
agents. Over time, I've been refining my Linux setup around those particular
ways of working.

Chrome is the more interactive, mouse-heavy half. It's where I browse websites,
consume information, make transactions, and use web applications, for both
personal things and work. That part of my day still benefits from a comfortable
graphical desktop.

It's also what keeps ordinary graphical file management relevant. If I've just
downloaded something, clicking to open it is natural. If I need to send a file,
choosing it in a file picker is natural too. Dolphin and those everyday file
interactions have a place in the setup, even though I usually handle system
management in a terminal or with an agent.

Then there's the terminal side. I love terminal life. Mechanical keyboards are
one of my hobbies, and I enjoy having a workflow that lets me do so much from
the keyboard.

I like the explicitness and reproducibility of commands and configuration. It's
the same appeal that infrastructure as code has for me: being able to describe
how something works, repeat an operation, and keep track of the configuration
behind it. I also value the low resource usage and flexibility of terminal
tools. Moving between a laptop, server, and workstation, or working remotely,
fits naturally into that workflow.

Agents are a big part of this now. A terminal and text-based configuration give
an agent something it can inspect and work with directly. That makes it easier
to ask for help investigating an issue, making a change, or taking over a task.
It's closely connected to why I enjoy this way of using a computer.

This also explains a lot of the move away from DMS. A visual interface for
system settings used to be appealing. These days, I'd often prefer to ask an
agent to look into something than go fishing through settings panels myself.
Having the system's behavior expressed through understandable configuration
and smaller services fits how I want to maintain it.

I used KDE for years. When I moved to Niri, I kept KDE around as a backup, but I
never opened it once. Eventually, I removed it. I love the Niri setup I've ended
up with, and it has become the desktop I want to use every day.

The surrounding pieces have changed as I've figured out what works for me.
DMS was part of that process, and it eventually gave way to a more minimal,
customized arrangement. The SwayNC fork, Rofi Plus tools, and smaller desktop
integrations have grown out of that continued refinement.

Niri Plus is a way to give this setup and its story a home. I want to show what
it's like to use, explain why the pieces are there and how they work together,
and provide useful instructions for someone who wants to try parts of it. The
scope is a personal desktop setup with its own documentation and presentation;
I don't want to take on the work of maintaining a distribution.
